# Learnings

What `new-episode` runs have taught, distilled from their `run-log.md` entries and `docs/episodes/runs.csv`. Each lesson is a change to the template pipeline, a reference or `SKILL.md`; when one lands, its entry here says where it went. Read this before tailoring a pipeline.

## Lessons

From the first run, `onboard-ai-like-a-colleague` (run id `2026-10-12T19:22:40Z`, template `5b77640`, draft PR #98). Each lesson names its evidence in that run's `run-log.md` and the change it proposes. Applied lessons say so at their end.

1. **The orchestrator cannot call `implement-spec`.** `references/implement-episode.md` tells the orchestrator to call the Skill tool with `implement-spec`. The skill sets `disable-model-invocation: true`, so the tool refuses it, and Han had to type `/implement-spec`. Proposed fix: drop the flag, or have the reference tell the orchestrator to ask Han to run it. Applied (#117): `implement-episode.md` asks Han to type `/implement-spec`, a vendored skill.
2. **No job designs a Slide the catalog lacks.** `write-dossier` labels such Slides `No catalog match`, `write-spec` turns each into a design question, and the tickets tell the implementor to stop. In this run five of nine Slides would have been left unbuilt. Han had one `ui-ux-pro-max:slides` subagent per ticket write a `Design answer` into the ticket body. Proposed fix: add a `design-slides` job between `write-dossier` and `write-spec`, with a reviewer. It reads the Dossier, the existing Slide layouts and FE-002/FE-004/FE-011, and writes one design per unmatched Slide. Open question: does it write into the Dossier or into its own staging file? Decided instead: a `write-design-spec` job after `write-spec` designs every Slide into its ticket body, behind a triage-label gate (`docs/handoff/write-design-spec-decisions.md`).
3. **A motion must be one a Slide can import.** The staging test (`tests/docs/episode-staging.test.ts:66-80`) accepts any `animations/*.client.tsx`, so `liquid-ink-transition` passed. But FE-007 (`.dependency-cruiser.cjs`) bars Slide and Episode files from importing `animations/`, and the effect is a full-viewport scroll overlay. Han had the Episode built without motion. Proposed fix: the test accepts only motions a Slide may import (none today), and `write-dossier.md` says to leave motion out when none exists. Decided: `motion:` resolves in the Slide library, and `write-design-spec` may overrule it (`docs/handoff/write-design-spec-decisions.md` 15).
4. **"Catalog" is an undefined term, and every job needs a shared base reading set.** `write-dossier.md:14-15` coins "catalog", which `GLOSSARY.md` lists under _Avoid_. Proposed fix: name the term in `GLOSSARY.md`, or replace it. Add a pipeline-level `context: [GLOSSARY.md, docs/episodes/<slug>/brief.md]` that the orchestrator adds to every agent's `references`, and that the staging test checks for existence. Decided: "catalog" becomes **Slide library** and **Master slide**, and every reviewer judges glossary terms as a baseline line (`docs/handoff/write-design-spec-decisions.md` 14, 16).
5. **The visual check measured unmounted Slides.** An Episode mounts a Slide's content only near the viewport. The probe command in `references/implement-episode.md` loads the page once, so every Slide off screen measured as an empty 800 px box. Proposed fix: load each Slide by its own `#<section>--<slide>` URL, as attempt 2 did, and record the count of mounted descendants beside the box. Applied (#117): `implement-episode.md` loads each Slide by its own URL and records the mounted descendant count.
6. **Post-build expectations fall between the tickets.** `docs/features/episode-migration.md` step 8 has two post-build steps: capture `tests/post-build/episode-text/<ep>.{en,de}.json`, and add the slug to `PUBLISHED_SLUGS`. No ticket owned them, and implementers are told not to build, so attempt 1 failed `test:build`. Proposed fix: `write-spec.md` gives step 8 to the wiring ticket, or `implement-episode.md` gives it to the orchestrator after the last merge. Applied (#117): `write-spec.md` gives step 8 to the wiring ticket.
7. **The Title slide has no Voice script slot.** Manuscript h1 P1 had no place to go. Attempt 2 voiced it as the first segment of the first section slide. Proposed fix: `write-spec.md` maps the h1 paragraphs to that segment. Promote that to a kit slot only through an ADR.
8. **The review's fixed point must be the Episode branch, not `main`.** The Episode branch carries the unmerged template branch, so the merge-base with `main` pulls in the whole template diff. This run used the commit before `implement-episode`. Proposed fix: `references/implement-episode.md` names the last commit before the job as the fixed point. Applied (#117): `implement-episode.md` names the last commit before the job.
9. **`open-pr` assumes base `main`.** Han kept PR #98 on base `feat/89-new-episode`, so the trial reads beside its template. Proposed fix: `open-pr.md` keeps an existing PR's base. Applied (#117): `open-pr.md` keeps an existing PR's base.
10. **A gate job reads `done` once its draft is logged.** `npm run episode:status` reads only the run log, so it showed `write-manuscript` as done before Han approved it. Step 5's checks catch only the Brief and pipeline gates. Proposed fix: the status script reads the output's `status:` for a job with `gate: human`, and prints `gate` until it is `approved`. Applied (#117): `status.pure.ts` prints `gate` until the output's `status:` is `approved`.
11. **`write-spec.md` contradicts itself.** It asks for Voice script segments "verbatim" and also says never to paste staging text. Proposed fix: point at paragraphs by anchor and number, and keep "verbatim" for the built Voice script. Applied (#117): `write-spec.md` points at paragraphs by anchor and number.
12. **`next dev` rewrites `AGENTS.md`.** Every subagent that started the dev server had to revert it. Proposed fix: a line in the `visual-check` skill, or have Next skip generating it. Applied (#117): `agentRules: false` in `next.config.ts`.

Gate diffs: Han changed only `status:` in the Brief and Manuscript gate pairs, and the pipeline pair mixes his approval with the template merge. No correction recurs, so no rubric line comes from them yet.

### Isolated sales run on Sol

`never-too-early-sales`, run `2026-10-13T22:50:35Z`, template `7ac7829`, integration branch `sales-pipeline-episode-sol`, spec #153. Evidence is in `docs/episodes/never-too-early-sales/run-log.md`, `visual-check.csv` and `docs/episodes/runs.csv`. These are proposals for a later template change; this run's approved pipeline and binding ADRs were not changed.

1. **An Episode label is not a run identity.** Another experiment's #147 shared `episode:never-too-early-sales`. This run added `run:sales-pipeline-episode-sol`, created #153, and used explicit ticket IDs without reading or editing the other experiment. Proposed fix: carry the integration branch and spec issue ID through the per-run pipeline/status reader, rather than discovering a spec from the first issue with the Episode label.
2. **Research category IDs have a grammar, not only a meaning.** Categorization proposed B2B, which passed its markdown check but failed the pipeline's research-folder check; the corrected ID is BIZ. Proposed fix: validate proposed folder names with the existing research-folder checker before committing categorization, so an upstream naming mistake is caught before a zero-retry pipeline job consumes it.
3. **Citations are numbered within each note.** The Dossier used Slide-wide `[2]`, `[3]` markers, while the renderer indexes each note's own `sources` array from 1. Implementers preserved the words and URLs but had to normalize the markers. Proposed fix: make the per-note numbering explicit in `write-dossier.md`, its sample and the staging check.
4. **A visual target is not necessarily a note target.** The kit's `target()` accepts declared note targets; design-only markers such as volume and funnel need plain `data-target` attributes. Proposed fix: distinguish note targets from other visual markers in the design-answer procedure instead of prescribing the typed helper for both.
5. **Real drawer state and native animation state matter.** The real matrix found a mobile stamp escaping its inset and inherited Title glows running while near. Equivalent-width checks had missed them. The first matrix also incorrectly rejected an inherited decorative loop while active; the corrected check observes its native pause state without pausing it itself. Proposed fix: make the visual procedure measure actual open/closed/beside/over states, inherited loop duties and visible descendant bounds, recording requested and effective modes below xl.
6. **Two production outputs are not an independent expectation.** German fallback tests compared the German render with the English render, and an Upcoming anchor case derived its expected IDs from the same production record/helper as the export. Controlled mutations showed those cases could pass the wrong contract. The code now uses written text and reviewed capture IDs (`455fdf2`); ARCH-003 already states the rule. Proposed fix: call these patterns out in the implementation/reviewer examples, not add another ADR or waive the rule because prior art does it.
7. **Automatic merges can evade the agent mark.** One worker's `git merge` created unmarked `50a3a1f`. Integration excluded that merge, retained the original audit branch and carried the marked fixes/data through properly marked commits without rewriting history. Proposed fix: explicitly require `git merge --no-commit` followed by the commit skill whenever a merge creates a commit, including a worker catching up to integration.
8. **Tool names need a runtime preflight.** This CLI had the base UI/UX skill but not the named slides add-on, and human-only `implement-spec` was not registered with its Skill tool. The run disclosed the design adapter and used the checked-in procedures; Han explicitly entered `/implement-spec #153`. Proposed fix: preflight the required tool/skill capabilities before the pipeline gate and record the supported adapter, rather than discovering the mismatch at implementation.

Han pre-approved the later gates, and the approval commits/ticket edits remained agent-marked. He made no repeated unmarked content corrections between draft and approved gates, so this run proposes no new writing-style rubric line. No governance decision or always-loaded agent instruction was added: the testing and loop duties already exist in ARCH-003 and FE-009.

## Next steps

Planned, not yet built, in the order they pay off:

1. **A mechanical runner.** The orchestrator is one Claude Code session reading `pipeline.yml` as a todo list. Its first piece exists: `npm run episode:status -- <slug>` (`scripts/status.pure.ts`) derives every job's state from `pipeline.yml` and `run-log.md`, so a todo list is rebuilt from disk. The target is a runner that reads the same file: either a Workflow script that walks the `needs` graph, or tasks the skill writes for agents to pick up from a queue. `pipeline.yml` is already shaped for it (stages as `needs`, agents in order, `retries`, `gate`).
2. **A subagent-stop telemetry hook.** Today the orchestrator writes each runs CSV row by hand from the Agent result. A `SubagentStop` hook (or `turn.complete`) appends the row itself, so no row is skipped or misread. OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY`) waits until a fleet of sessions needs it.
3. **Agent profiles.** Every agent's `profile:` is `~`. Later it names a profile (model, tools, persona), with no schema change beyond the value.
4. **Revisit Cowork voice.** As of October 2026 Cowork has dictation only, so the voice Brief grill runs in Claude Desktop and ends in a handoff. When Cowork gains two-way voice, check whether it can run the grill and write `brief.md` directly.
5. **Add back the draft gate.** The gate after `write-manuscript`, for Han to read the Manuscript before the spec is written, was removed. It came back as `gate: human` on the `write-voice-script` job of the template (#106), where Han reads the whole Dossier.
6. **One `harvest-run` skill at Promotion.** Before the staging folder is deleted, it turns Han's gate edits (Brief, Manuscript, the ticket edit history) into the profile guides, `docs/design/design-guide.md` included, and the run log's prefixed findings and `runs.csv` into lessons here. It replaces issue 89's `harvest-human-profile`. It reads the agent marks with `agentOf` (`scripts/marks.pure.ts`): an unmarked commit or ticket edit is Han's.
7. **`promote-episode` rewrites the Dossier's Visuals from the built Slides**, with a reviewer, so a promoted Dossier reflects the implementation, not the first idea.
8. **Drop the design gate on evidence.** Remove `gate: human` from `write-design-spec` once its run-log Metrics show most tickets approved as drafted across runs.
