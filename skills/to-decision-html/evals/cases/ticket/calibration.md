# Calibration answers

My answers to anything you would ask before building. Where a question is not answered here, proceed and mark the value you chose as assumed.

- **Mode:** `explain`. The decisions are settled; the reader learns them and sends questions.
- **Audience:** an engineer new to the project who will implement or review similar work. They know TypeScript, browser storage and hashing, and only the project vocabulary the issue itself uses.
- **Items:** propose your own, one per settled decision, ordered by consequence.
- **Depth:** `both` on the item about a stored entry whose hash differs, `simple` on every other item.
- **Fidelity:** the lowest rung that makes each decision clear; the note offering "Download old progress" or "Discard" at `wireframe` or higher.
- **Questions:** the reader's questions go to the issue's author.
- **Allowed Next actions and Gates:** none. Nothing is approved from this page.
- **Design guidance:** none supplied. Use a restrained, readable style with light and dark themes.
- **Vocabulary:** use the issue's terms as written: run, Workflow, Episode, progress key, entry, pair hash, prefs storage module.
- **Motion library:** none named.
- **Feedback route:** your default, at the destination the run instructions give.
