1. Tour and headless judge share one beat plan and one Sampler

Worth exploringin-process
  • beat-means.pure.ts
  • factory-tour.pure.ts
  • factory-scenario.pure.ts
  • factory-run.pure.ts

Before: shallow, leaking

aimAtStepreadMeanFactoryRun.aimedplayStepsreadBeatsrunAveraged

window rule written twice; got[] mutated in place

After: deep

beatsOf + Sampler
tourjudge

Problem. The tour (aimAtStep, backTour, readMean) and the judge (playSteps, readBeats, runAveraged) each recompute a beat's set, end step, sample steps and keys, and FactoryRun carries tour state (aimed, stopAt, arrived, sampled) behind a Sampling whose readonly got is filled in place.

Solution. One pure beatsOf(steps, t0k) plan (set, from, end, sampleAt, keys) and a Sampler (at, keys, readings(), stepThrough(f,k,n)) replace the shared mutable list; FactoryRun.advance takes the aim as an argument instead of storing it.

  • leverage: one plan, two callers
  • locality: window rule in one place
  • Sampling.got mutation gone
  • FactoryRun loses 4 tour members

ADR: None. ADR 0024 §10/§12 demands both read the same steps; this makes it structural.

Problem. factory-still-state.ts (201 lines) makes 12 deep imports into painter, layout and stage internals and re-implements the painter's document merging and rack slots; the hero preview carries a second copy of card and slot geometry. A painter change breaks a Slide silently.

Solution. Add stillOf(useCase, state, locale) in the Explorable (stills.pure.ts) returning FactoryStillState; the Slide imports that one module and keeps only its markup. Hero preview stays out of scope until its geometry has a second reader.

  • 12 imports become 1
  • geometry changes stay local
  • painter and still merge rule share code
  • stills test moves with the module

ADR: FE-007 §3/§5 allow Slides to import src/explorables, so no conflict; FE-012 §3 requires the new module to own no route or Episode metadata.

3. One state-entry module for preset, tour, reset, use case and file load

Worth exploringin-process
  • software-ecology.client.tsx
  • reset-state.ts
  • use-exchange-wiring.ts
  • use-run.ts
  • state-defaults.pure.ts
  • use-display.ts

Before: shallow, leaking

onPresetonTouronResetonUseCaseloadInto

same 5 steps, 5 orders; Parts bag everywhere

After: deep

enterState(B,id) + useEnterState
5 callers

Problem. Five handlers (onPreset, onTour, onReset, onUseCase, loadInto) each repeat dismiss dashboard, end tour, show view, apply compare, set run in a slightly different order, and the client leaf (239 of 250 lines) passes the whole Parts bag to Stream, compareWidgetOf and the exchange wiring.

Solution. A pure enterState(B, id) returns {view, compare, display, settings, speed} (extending defaultsOf) and one useEnterState hook performs dismiss, show and apply in one order; the five callers pass only an intent. Parts shrinks to named slices.

  • leverage: one order, five callers
  • locality: new overlay closes once
  • client leaf drops under cap
  • pure plan testable without DOM

ADR: FE-001 §1 (transient state) and FE-012 §4.1 (parent owns state) stay intact.

Problem. nameOf re-reads roles.words.yml and indexes words.en.scenarios[id].claims directly, bypassing presetName and scenarioWords, so a catalog-level scenario fallback would show on the page and not in ecology:sim. loadUseCase also repeats the suffix naming that use-case-data.ts keeps as SOURCES.

After: deep

Problem. zod is a superRefine shell around about 600 lines of hand rules over Map_, and readUseCase then casts doc as UseCaseData, so the types (235 lines, near the cap) and the validators drift independently. The retired swing name is also migrated in use-case-file, presetOf and unretired.

Solution. Express the structural rules as zod object schemas whose z.infer is UseCaseData; keep cross-reference rules (ids, routes) as superRefine with the same messages. Migrate retired names once at the read seam.

  • type and check share one source
  • types.ts leaves the 250 cap
  • cast removed
  • one migration site

ADR: ADR 0024 §11 fixes the messages (ported from the reference build): reuse them verbatim; large, so not Strong.
