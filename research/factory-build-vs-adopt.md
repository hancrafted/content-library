# Build vs adopt: tools for the Factory's Job, harness, eval and tracing needs

Research for [#462](https://github.com/hancrafted/content-library/issues/462), child of map [#456](https://github.com/hancrafted/content-library/issues/456). Read on 2026-10-30 from primary sources (official docs, source READMEs, specs, GitHub API, npm and PyPI download APIs). Throwaway branch: never merged.

**The Factory's needs, as the brief frames them:** a Job defined in YAML with a declared input manifest (static items, plus dynamic items recorded once and replayed); a Worker (`claude -p` with a fixed agent profile, another agent, a script, or Han); a Station (the harness the Worker runs in); graders (check, LLM judge, human gate); repeated trials per variant for ablation; traces into the existing append-only JSONL spans (design-ADRs 0007–0010); TypeScript preferred.

## Verdict in one paragraph

Every layer except one has mature prior art: runners with trials (Inspect AI epochs, promptfoo `--repeat`, Braintrust `trialCount`, LangSmith `num_repetitions`), graders of all three kinds, record/replay with explicit miss policies, and a span vocabulary (OTel GenAI) that Claude Code already emits. None of them makes **the Job's inputs a declared, named, individually removable list**: context lives inside the solver, the prompt, the provider config or the agent's filesystem. That manifest, plus the Station that turns it into an isolated Claude Code run, plus a pipeline that chains such Jobs with human gates, is what is uniquely ours. The closest adoptable runner in TypeScript is promptfoo; the best reference design is Inspect AI (Python); the Worker integration should sit directly on `claude -p` / the Claude Agent SDK, whose isolation switches (`--bare`, `settingSources: []`, `--allowedTools`, `--agents`) are exactly the levers an ablation needs.

## Per candidate

### Inspect AI

- **Covers.** A Task is "a recipe for an evaluation consisting minimally of a dataset, a solver, and a scorer"; options include `epochs`, `sandbox`, `approval`, `token_limit`, `cost_limit`, `early_stopping` and a log `viewer` ([Tasks](https://inspect.aisi.org.uk/tasks.html)). Epochs carry a count and reducers that combine per-epoch scores ([Metrics](https://inspect.aisi.org.uk/metrics.html)). Results land in an eval log browsed with `inspect view` ([Log viewer](https://inspect.aisi.org.uk/log-viewer.html)).
- **Claude Code as Worker.** The sandbox agent bridge runs CLI agents "within sandboxes (e.g. Claude Code, Codex CLI, or Gemini CLI)" and proxies their model calls through Inspect ([Agent bridge](https://inspect.aisi.org.uk/agent-bridge.html)). `inspect_swe.claude_code()` exposes `system_prompt`, `skills`, `mcp_servers`, `disallowed_tools`, `subagent_model`, `version`, and a `centaur` mode that hands Claude Code to a human ([inspect_swe Claude Code](https://meridianlabs-ai.github.io/inspect_swe/claude_code.html)).
- **Manifest.** Task parameters make variants without code changes ([Tasks § Parameters](https://inspect.aisi.org.uk/tasks.html#parameters)), and `skills=` is a list. But context is not a first-class named list with per-item removal; an ablation is a parameter you write by hand.
- **Fit.** The best-matching model of Job = dataset + solver + scorer + epochs + sandbox. Python-only, and it routes model calls through its own proxy, so the Claude Code subscription path and our JSONL spans would both sit behind Inspect's abstractions. Adopt the vocabulary and design; adopting the runtime means a Python island.

### promptfoo

- **Covers.** YAML config, `promptfoo eval` with `--repeat <n>` ("Number of times to run each test"), a disk cache disabled by `--no-cache`, `retry`, `export`, and `promptfoo view` ([CLI](https://www.promptfoo.dev/docs/usage/command-line/), [Caching](https://www.promptfoo.dev/docs/configuration/caching/)).
- **Claude Code as Worker.** Provider `anthropic:claude-agent-sdk` (alias `anthropic:claude-code`) wraps the TypeScript Agent SDK with `working_dir`, `copy_working_dir` (fresh copy per step), `append_allowed_tools`, `disallowed_tools`, `agent`, `agents`, `skills` (filter which skills load), `setting_sources` (disabled by default), `hooks`, `max_budget_usd`, `cache_mcp`, `output_format` ([provider docs](https://www.promptfoo.dev/docs/providers/claude-agent-sdk/)).
- **Manifest.** The closest of any runner: `skills`, `setting_sources`, `agents` and `working_dir` are per-provider knobs, so a variant matrix can drop one. Still config fields of one provider, not a Worker-neutral, named input list; dynamic context (web search) is not recorded per item.
- **Fit.** TypeScript, MIT, clears ARCH-001. A good candidate to run a Job's offline experiments, or to borrow assertion and cache design from. It is an eval runner, not a pipeline of gated Jobs.

### Braintrust and LangSmith (concepts)

- **Braintrust.** An experiment is "an immutable snapshot of an evaluation run", comparable across runs ([Experiments](https://docs.braintrust.dev/evaluate/run-evaluations)); `trialCount: 10` runs each input ten times to measure variance ([Advanced evals](https://docs.braintrust.dev/evaluate/advanced-evaluations)).
- **LangSmith.** Offline evaluation over datasets of examples (inputs + optional reference outputs + metadata), online evaluation over production runs and threads ([Evaluation concepts](https://docs.langchain.com/langsmith/evaluation-concepts)); `num_repetitions` repeats each example ([Repetitions](https://docs.langchain.com/langsmith/repetition)).
- **Fit.** Concepts worth taking: _immutable experiment_, _offline vs online_ (our "offline experiments" vs "runtime grading"), _example = inputs + reference_. Both are hosted platforms; adopting them puts traces off-repo, against the product vision's non-goal of a backend before horizon 3.

### Record/replay harnesses

- **agent-trace-harness.** Record → freeze → replay → diff → judge → calibrate. Modes `strict` (all recorded) and `counterfactual` (live model, recorded tools). A replay miss is `off_trace` with a policy `fail`, `mock` or `live`; near matches are `fuzzy_hit`. Agent version pins `prompt_hash`, `model`, `tool_schema_hash`. Includes a noise floor and judge calibration with Cohen's kappa ([README](https://github.com/NickYelton/agent-trace-harness)). Python, one author, no licence, 0 stars: a design reference only.
- **AgentReplay.** Intercepts "LLM responses, tool results, the clock, randomness" for LangGraph agents ([README](https://github.com/hassanzafarr/AgentReplay)). Python, LangGraph-bound, one author.
- **cambium PR #21.** JSONL cassette keyed by a hash of model, temperature, max tokens, system and user; modes `record`, `replay` (an unrecorded prompt raises `LLMCacheMiss`: "a replay must never silently go live") and `auto` ([PR #21](https://github.com/debarshi29/cambium/pull/21), merged 2026-10-02).
- **VCR-style in TypeScript.** nock records and replays HTTP fixtures (`nock.back`) ([README](https://github.com/nock/nock#nock-back)); Polly.js does the same but has not published since 2023. Both intercept HTTP inside a Node process, so they cannot reach the tool calls of a `claude` subprocess.
- **Fit.** The replay-miss question in #456 already has a well-named answer to borrow: miss policy `fail | mock | live`, with `live` marking the trial non-comparable, and the miss itself a signal. For Claude Code, the recording seam is the tool boundary (hooks or an MCP stub), not HTTP.

### OpenTelemetry GenAI semantic conventions

- **Covers.** Spans `create_agent`, `invoke_agent` (client and internal), `execute_tool` and `invoke_workflow`, keyed by `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.agent.name`, `gen_ai.request.model` ([agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md)); an event `gen_ai.evaluation.result` with `gen_ai.evaluation.name`, `score.value`, `score.label`, `explanation` ([events](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-events.md)). Status of all of it: **Development**. The GenAI conventions now live in their own repository, `open-telemetry/semantic-conventions-genai`.
- **Fit.** Adopt the _names_ in our JSONL spans (Job ≈ `invoke_workflow` / `invoke_agent`, grader result ≈ `gen_ai.evaluation.result`) so a later OTLP export is a mapping, not a migration. Don't take an OTel SDK dependency for an append-only file; the spec is unstable.

### Claude Code headless (`claude -p`)

- **Runner surface.** `-p` runs non-interactively; exit code 0 on success; `--output-format text|json|stream-json`; `--json-schema` puts validated output in `structured_output`; `json` output carries `total_cost_usd` and a per-model breakdown ([headless](https://code.claude.com/docs/en/headless)).
- **Isolation, i.e. the manifest levers.** `--bare` skips auto-discovery of "hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and CLAUDE.md"; context is then passed only by flag: `--append-system-prompt(-file)`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`; `--add-dir` loads only that folder's skills. `--bare` "will become the default for `-p`" and needs `ANTHROPIC_API_KEY`, not the subscription login ([headless § bare mode](https://code.claude.com/docs/en/headless#start-faster-with-bare-mode)). `--allowedTools` pre-approves tools. Subagent profiles fix `tools:` and `model:` in frontmatter ([sub-agents](https://code.claude.com/docs/en/sub-agents)).
- **Hooks as the record/replay seam.** `PreToolUse` can block a call; `PostToolUse` `updatedToolOutput` "replaces the tool's result" ([hooks](https://code.claude.com/docs/en/hooks)). Inference, not tested: recording = a PostToolUse hook that appends tool input and output; replay = serving the recorded output, with a miss policy when the input is new. A PostToolUse replacement still lets the live tool run first, so a true offline replay probably needs an MCP stub tool in place of WebSearch.
- **Tracing.** OTel metrics and events, plus traces (beta): a `claude_code.interaction` root span with `claude_code.llm_request` and `claude_code.tool` children, subagent spans nested under the Agent tool span, `gen_ai.*` attributes on requests and tools; `TRACEPARENT` in the environment makes the interaction a child of the caller's span. Prompt, tool detail and tool content are redacted unless `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT` are set ([monitoring](https://code.claude.com/docs/en/monitoring-usage)).
- **Fit.** The natural Worker. It is not a runner, grader or trial loop. Licence is proprietary; it is already used in this repo as a tool, not a library.

### Claude Code skill-creator evals

- **Covers.** `evals/evals.json` test prompts; for each case two subagents launched in the same turn, one `with_skill` and one baseline (`without_skill`, or `old_skill` from a snapshot); a grader agent writes `grading.json` (`text`, `passed`, `evidence`); `scripts.aggregate_benchmark` writes pass rate, time and tokens "with mean ± stddev and the delta"; an analyst pass flags non-discriminating assertions and high variance; `eval-viewer/generate_review.py` shows results, with `--previous-workspace` across iterations ([SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)). Licence Apache-2.0 (`skills/skill-creator/LICENSE.txt`).
- **Manifest.** An ablation of exactly one item, the skill under test. It is the brief's core question in miniature, but the runs are subagents inside one interactive session, not isolated headless trials, and nothing else in the context is held fixed or recorded.
- **Fit.** Copy the method (paired with/without, mean ± stddev, non-discriminating assertion check, viewer fields); don't depend on it.

### Claude Agent SDK

- **Covers.** "Claude Code as a library" in TypeScript and Python: built-in tools, hooks, subagents, MCP, permissions, sessions, skills, plugins ([overview](https://code.claude.com/docs/en/agent-sdk/overview)). `settingSources` decides which filesystem settings load; omitted = `["user", "project", "local"]`; `[]` limits the agent to what is configured programmatically; managed policy and `~/.claude.json` are read regardless ([Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)). Third-party products may not offer claude.ai login; use API key auth ([overview](https://code.claude.com/docs/en/agent-sdk/overview)).
- **Fit.** The TypeScript-native way to build the Station: typed messages instead of parsing stream-json, hooks as functions, `settingSources: []` plus explicit `skills`/`agents` as the manifest's enforcement. Licence: TS package proprietary, "subject to Anthropic's Commercial Terms of Service" ([LICENSE.md](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/LICENSE.md)); clears the other ARCH-001 signals. Trade-off against plain `claude -p`: isolation (`--bare` / `settingSources: []`) and the SDK both lean on an API key, while non-bare `claude -p` can use the subscription login but then loads whatever `.claude/` holds.

## What is uniquely ours

1. **The input manifest.** A Worker-neutral, named list of a Job's inputs (skills, ADRs, AGENTS.md, Brief, recorded retrievals), each item addressable so a variant is "manifest minus item X". No surveyed tool has it; each hides context in a solver, prompt or provider config.
2. **Dynamic context as a manifest item.** A recorded web search or retrieval that is graded, frozen and then listed like a static file. Record/replay tools freeze tool responses to stabilise a run; none treats a recording as a removable, gradable input.
3. **The Station for Claude Code.** Turning a manifest into an isolated `claude -p --bare` / Agent SDK run (`settingSources: []`, explicit `--agents`, `--add-dir` skills, `--allowedTools`), with tool-level record/replay. Inspect's `inspect_swe` is the nearest, in Python, behind its own model proxy.
4. **A pipeline of gated Jobs.** Jobs chained by outputs with foreach and explicit human gates (Brief, Spec HTML), where the same graders serve runtime grading and offline experiments. Eval tools stop at "one task, many samples".
5. **Our run log.** The JSONL spans of design-ADRs 0007–0010 stay; borrowing OTel GenAI names keeps an OTLP export open.

## Build vs adopt, as input for #464 and #466

- **Build:** manifest schema, Job YAML, Station (on `claude -p` or `@anthropic-ai/claude-agent-sdk`), pipeline with gates, recorder/replayer at the tool boundary, trial loop and report. All small in TypeScript once the Worker is Claude Code.
- **Borrow names and designs:** Inspect (task/sample/solver/scorer/epochs/reducers), Braintrust (immutable experiment), LangSmith (offline vs online), agent-trace-harness (strict vs counterfactual replay, `off_trace` miss policy, noise floor, judge calibration), skill-creator (paired baseline, mean ± stddev, non-discriminating assertions), OTel GenAI (span and evaluation-event attribute names).
- **Adopt as dependency, if anything:** `@anthropic-ai/claude-agent-sdk` (Worker), and possibly `promptfoo` for cross-model checks (R15) where a Job is a plain prompt. Both clear ARCH-001's four signals; the SDK's proprietary licence is a human call.
- **Avoid:** hosted platforms (Braintrust, LangSmith) before horizon 3; single-author record/replay repos; Polly.js (stale).
