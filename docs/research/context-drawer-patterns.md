# Context drawer patterns

Research date: 2026-10-08. Scope: a right-side drawer (Speaker notes / Voice script tabs) over a statically exported Next.js site, bottom sheet on narrow viewports. Not binding; binding decisions live in `.archgate/adrs/`.

- **Non-modal, complementary region, not a dialog.** The drawer is a reference panel read beside the content, so keep the page interactive. Native `<dialog>.show()` leaves nothing inert, draws no backdrop and ignores Escape by default; `closedby="closerequest"` makes Escape close it ([MDN `show()`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/show)). `showModal()` makes the page inert, so reserve it for blocking tasks. The APG modal pattern (focus in on open, Escape closes, focus returns to the opener) is a sound baseline for the open/close handoff ([APG dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)). It warns against `aria-modal="true"` unless the page really is blocked. Alternative: an `<aside>` (complementary landmark) that needs a label if more than one exists ([APG landmark](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/examples/complementary.html)). The `popover` attribute is a poorer fit: `auto` popovers light-dismiss on outside click, and closed ones are `display: none` ([MDN popover](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/popover)). Our own handler must restore focus to the opener on close; the sources above do not guarantee it for non-modal use.
- **Tabs per APG.** Roles `tablist` / `tab` / `tabpanel`; `aria-selected` on tabs; `aria-controls` tab to panel; `aria-labelledby` panel to tab; `tabindex="0"` on a panel whose first content is not focusable. Left/Right move between tabs and wrap, Home/End are optional, Tab leaves the tablist for the panel. Automatic activation is recommended only if panels show without noticeable latency; both panels are already in the DOM, so automatic is viable here ([APG tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)). Do not use `hidden` for inactive panels if they must print: the HTML spec says not to use `hidden` for content hidden in one view only, such as tab panels ([WHATWG hidden](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute)).
- **Keyboard shortcut.** WCAG 2.1.4 (Level A) covers shortcuts made of printable characters, including `?` and key sequences. Such a shortcut needs one of: a way to turn it off, a way to remap it to include Ctrl/Alt, or activity only while the component has focus. A modifier-based shortcut is exempt ([Understanding 2.1.4](https://www.w3.org/WAI/WCAG21/Understanding/character-key-shortcuts.html)). Prefer a modifier chord, and check it against browser and screen-reader keys; the spec excerpt I could read says nothing about specific conflicts, so test on real setups. `aria-keyshortcuts` only announces a shortcut and implements nothing ([WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/#aria-keyshortcuts); the section did not load in my fetch, so this is from the known definition and should be re-checked). Make it discoverable with a visible hint on the trigger button, plus the attribute.
- **Keep notes in the DOM, findable and printable.** Render both panels as server HTML. `hidden="until-found"` uses `content-visibility: hidden`, so find-in-page and fragment links match and reveal the content, firing `beforematch`. It needs layout containment (not `display: none/contents/inline`), keeps the element's box, and falls back to `display: none` in unsupporting browsers ([WHATWG](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute), [Chrome](https://developer.chrome.com/docs/css-ui/hidden-until-found)). Plain `hidden`, closed `popover` and closed `<dialog>` all compute to `display: none`, so they will not print without an override. Safer: hide the closed drawer with an off-screen or `visibility`-based style, not `display: none`. The spec says author CSS can override the hidden state, for example `display: block`. Neither source covers printing, so verify in a real print preview. In `@media print`, force both panels visible, static, and not clipped. Use `inert` on the closed drawer only if it is not `display: none`; this is my inference, not tested.
- **Responsive without JS or dependencies.** Switch side panel to bottom sheet with `@media` or `@container` size queries; `@container` is Baseline widely available since Feb 2023 ([MDN @container](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@container)). The repo already has Tailwind 4, which provides these. `package.json` has no Radix dialog or tabs, only `@radix-ui/react-slot`. Adding one would face [ARCH-001](../../.archgate/adrs/ARCH-001-dependency-admission-bar.md) (four-signal soft screen, `~x.y.z` range). Native elements plus a small `*.client.tsx` leaf for state and the shortcut ([FE-006](../../.archgate/adrs/FE-006-server-client-boundary.md)) need no new dependency.
