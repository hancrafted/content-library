# Human-in-the-loop Shared visual

Read before placing, changing or testing the human-in-the-loop Shared visual (`src/components/slide-shared/human-in-the-loop/`) or adding a Workflow to it. Binding rules: [FE-012 Shared Visual Content](../../.archgate/adrs/FE-012-shared-visual-content.md), [FE-006](../../.archgate/adrs/FE-006-server-client-boundary.md) §5, [FE-007](../../.archgate/adrs/FE-007-module-layering.md) §5 and [FE-011](../../.archgate/adrs/FE-011-design-tokens.md). This guide holds the detail that does not bind. A **Workflow** is defined in the [glossary](../../GLOSSARY.md).

## Placing it

A Slide renders `<HumanInTheLoop workflow="summer-party" locale={locale} diagram={…} />` from `human-in-the-loop.tsx`, the server entry. It reads the Workflows and the words of the locale at build time and hands them, serializable, to the one client parent `human-in-the-loop.client.tsx`.

- `words={{ ui }}` overrides the chrome words key by key. A Workflow has no words to override: its file is written in one language and renders as written.
- `diagram` carries the Slide's own markers, popovers, notes (`target`), gate words and the worked-chat button, keyed by stage and job id. Its `initials` draws each stage's BRIEF letters as circled capitals (English letters in German too, with German tooltips); a Slide that leaves the acronym unnamed says `initials: false`. The ai-attention-span Slide sets `initials: false` on purpose: the BRIEF acronym is shown only in the freelancer Episode (onboard-ai-every-time). `jobsLabel` is a template (`{stage}: jobs`) for every stage's list of jobs, `gateLabel` on a stage slot is the word for its gate, and a stage's or job's `popover` carries no title: the diagram titles it with the stage name. The sign-off card is the Workflow's (`card` on the stage), never a Slide's.
- `level`, `readonly` and `controls` set the start state. `readonly: true` hides every "Try it" button and the Technical toggle, so the Slide shows the diagram alone. `controls` is the Preset's override of the typed control registry in `toolbar-controls.pure.ts` (`picker`, `level`, `download`, `upload`), laid over it key by key, e.g. `{ picker: { show: false } }`.
- One pill toolbar, mirrored from the Context visual's (`human-in-the-loop.module.css`; FE-007 §5 bars a client leaf from importing the Context folder, so the tokens are copied, not imported): the Workflow pills, a separator, then icon buttons for Technical (`</>`), download and upload. One tooltip (`tip.client.tsx`) serves the toolbar icons, the BRIEF circles, the prompt icons, the Short toggle and the modal X: it shows on hover and keyboard focus, is hoverable, and Escape dismisses it before it reaches the dialog (WCAG 1.4.13); the controls keep their own `aria-label`, never `title`. The icon buttons are 36px (`size-9`), the same as the Context toolbar's 2.25rem; the BRIEF circles are 24px with a gap (WCAG 2.5.8). There is no Watch / Try switch: every stage column ends in a "Try it" button that opens the stage's modal.
- Naming against FE-012 §4.3: the ADR's `renderMode` is `level` here, one global value. There is no per-part override because no part has a Simple and a Technical view of its own; the Level changes only what a step copies.

## Parts

The parent owns all state (`workflow-state.pure.ts`), computes `workflowView` once per change and gives each part its slice: `toolbar-part`, `diagram-part`, `modal-part`. The modal is one information architecture for every stage: the title `<Stage>: Try it` with the learning goal under it, the simple/technical toggle and an X (Esc and the backdrop close too); on a wide screen the tasks as numbered Do and Review steps on the left and the details of the task in focus on the right (why it matters, the example result, what good looks like), on a phone one full-screen column with the details folded under each task. Each step is a `TryPrompt` (`core-components/try-prompt/`) collapsed by default, with paste-in slots, a marker per section purpose and Copy, ChatGPT and Claude icons (the chat links open a new tab with `?q=`). A fan-out shows Chat 1..N tabs in Simple and one orchestrator prompt in Technical, and its details one example per chat. FE-012 §4.5 asks for a pure `*-view.tsx` where a part can render alone; the diagram, its job cards and the modal compose client leaves and are only ever shown by a client part, so they stay plain `.tsx`. Every handoff is a markdown document drawn by the one generic renderer (`markdown-view.tsx`). The glyphs the visual draws live in `slide-shared/glyphs/`.

## Adding a Workflow

A Workflow is one YAML file per language. What is written renders as written; there is no locale inside a file.

1. Copy `summer-party.en.yml` to `<id>.en.yml` and `summer-party.de.yml` to `<id>.de.yml`. The shape is `workflow-schema.types.ts`: `scenario`, `purposes` (one explanation per prompt purpose), `techniques` (the catalogue of prompt techniques, `{ id, tier: basic | advanced, title, explain }`, defined once; adding one is a new entry, never a schema change), the general `reviewer`, `templates` (a markdown handoff per `kind`, with the required H1 and H2s) and `stages`, each with `tasks`.
2. A task has `output`, a `template`, `slots`, a `do` prompt per runtime (`simple`, `technical`; ordered sections with a `purpose`), an optional `instructions` (one or two plain sentences on what the user does, shown in the "What to do" panel; so does `review.instructions`), an optional `review` and `details` (`why`, `example`, `goodLooksLike`, optional `techniques`). A section (also a `reviewer` one) may list `techniques` ids next to its one `purpose`: its purpose tooltip then lists them with their tier. A task's `details.techniques` are listed under "why it matters". The loader rejects an unknown id, a repeated id and an entry without a tier; tag only where a technique genuinely applies. A slot id names the `output` of a task in an earlier stage, and the diagram draws its edges from the slots. A `free: true` slot is the user's own text (Plan's `task`) and names no output; with no `sample` it takes the `scenario` (summary, then the facts as a list) as its sample.
3. Markers in section text: `{{slot}}`, `{{slot_K}}` for the Kth entry of a `multiple` slot, `{{n}}` in a fan-out, `{{template}}`, and in the `reviewer` `{{inputs}}` and `{{checks}}`. A slot's `sample` stays in the prompt while the slot is empty; a `multiple` slot carries a list, one sample per marker. A `fanOut: N` task makes N chats; its `example` is a list of N, one per chat, and the Compare slot over it carries the same N as its samples.
4. Keep scenario facts out of the prompt sections: they live in `scenario`, the slot samples and the examples.
5. Register the pair in `workflow-data.ts` (`FILES`, `WORKFLOW_IDS`). `workflow-pair.test.ts` holds both files of a Workflow to the same structure (FE-012 §1.3: stage, task and slot ids, slot modes, sample and example counts, section purposes), and the loader checks every sample and example against its template. The build throws each problem of a shipped file.
6. Viewers may also upload a Workflow file (the same shape, in any language); problems are listed under the toolbar and the authored Workflow stays. A download writes the current file as it is; pasted values are not exported.

## Testing

- Fast suite: `*.pure.test.ts` and `*.test.ts` beside the files (Workflow loading, the pair structure, view model, state, markdown handoffs).
- Browser seam: `human-in-the-loop.browser.test.ts`, local only (`npm run test:browser`), drives the Slides Episode's "Human in the loop" Slide in the shared headless Chrome: the pill toolbar, a stage's Try it modal (title with learning goal, the simple/technical toggle and X, two columns on desktop with the details following the focused task, full screen on a phone with the details folded under each task, Chat 1..N tabs and the Technical orchestrator, "Open in" written out or icon only, collapsed prompts, copy, chat links, "Copied", backdrop, X and Escape close), Compare's one multiple research slot with its three samples, one example per Research chat, every stage of both Workflows in English and in German (`/de/episodes/slides/`) with no unfilled marker, Vacation with its own card lines, a broken and a valid upload, axe in light and dark, and phone width. `HITL_URL` names the page (default `http://localhost:3000/episodes/slides/`), served by `next dev` or `npm run preview`.
- Episode text captures (`tests/…/episode-text`) include the toolbar words; recapture them when a word changes.
