# Human-in-the-loop Shared visual

Read before placing, changing or testing the human-in-the-loop Shared visual (`src/components/slide-shared/human-in-the-loop/`) or adding a Workflow to it. Binding rules: [FE-012 Shared Visual Content](../../.archgate/adrs/FE-012-shared-visual-content.md), [FE-006](../../.archgate/adrs/FE-006-server-client-boundary.md) §5, [FE-007](../../.archgate/adrs/FE-007-module-layering.md) §5 and [FE-011](../../.archgate/adrs/FE-011-design-tokens.md). This guide holds the detail that does not bind. A **Workflow** is defined in the [glossary](../../GLOSSARY.md).

## Placing it

A Slide renders `<HumanInTheLoop workflow="summer-party" locale={locale} diagram={…} />` from `human-in-the-loop.tsx`, the server entry. It reads the Workflows and the words of the locale at build time and hands them, serializable, to the one client parent `human-in-the-loop.client.tsx`.

- `words={{ ui, workflow }}` overrides the chrome words and the shown Workflow's words, key by key. Prefer the Workflow's own words; override only what the Slide says differently (both shipped Slides override none).
- `diagram` carries the Slide's own markers, popovers, notes (`target`), gate words and the worked-chat button, keyed by stage and job id. Its `initials` draws each stage's BRIEF letters as circled capitals (English letters in German too, with German tooltips); a Slide that leaves the acronym unnamed says `initials: false`. The ai-attention-span Slide sets `initials: false` on purpose: the BRIEF acronym is shown only in the freelancer Episode (onboard-ai-every-time). `jobsLabel` is a template (`{stage}: jobs`) for every stage's list of jobs, `gateLabel` on a stage slot is the word for its gate, and a stage's or job's `popover` carries no title: the diagram titles it with the stage name. The sign-off card is the Workflow's (`words.stages.<id>.card`), never a Slide's.
- `level`, `readonly` and `controls` set the start state. `readonly: true` hides every "Try it" button and the Technical toggle, so the Slide shows the diagram alone. `controls` is the Preset's override of the typed control registry in `toolbar-controls.pure.ts` (`picker`, `level`, `download`, `upload`), laid over it key by key, e.g. `{ picker: { show: false } }`.
- One pill toolbar, mirrored from the Context visual's (`human-in-the-loop.module.css`; FE-007 §5 bars a client leaf from importing the Context folder, so the tokens are copied, not imported): the Workflow pills, a separator, then icon buttons for Technical (`</>`), download and upload. One tooltip (`tip.client.tsx`) serves the toolbar icons, the BRIEF circles, the prompt icons, the Short toggle and the modal X: it shows on hover and keyboard focus, is hoverable, and Escape dismisses it before it reaches the dialog (WCAG 1.4.13); the controls keep their own `aria-label`, never `title`. The icon buttons are 36px (`size-9`), the same as the Context toolbar's 2.25rem; the BRIEF circles are 24px with a gap (WCAG 2.5.8). There is no Watch / Try switch: every stage column ends in a "Try it" button that opens the stage's modal.
- Naming against FE-012 §4.3: the ADR's `renderMode` is `level` here, one global value. There is no per-part override because no part has a Simple and a Technical view of its own; the Level changes only what a step copies.

## Parts

The parent owns all state (`workflow-state.pure.ts`), computes `workflowView` once per change and gives each part its slice: `toolbar-part`, `diagram-part`, `modal-part`. The modal is one information architecture for every stage: the title `<Stage>: Try it` with an X top right (Esc and the backdrop close too); the numbered steps (Run, Check in a fresh chat, optional Make it a page), each one `todo` line over a prompt collapsed by default whose row holds Copy, ChatGPT and Claude icons (the chat links open a new tab with `?q=`); then the explanation (what it does, in and out, what good looks like, skills, the example result). The Short toggle on the interview's Run step swaps in `run.short`; it applies to the Simple prompt, not to the Technical `/skill` command. FE-012 §4.5 asks for a pure `*-view.tsx` where a part can render alone; the diagram, its job cards and the modal body compose client leaves (`node-popover.client`, `diagram-try.client`, the ticket graph) and are only ever shown by a client part, so they stay plain `.tsx` (the lint rule bars a `*-view.tsx` from importing a client leaf). The output views in `outputs/` are `*-view.tsx`; anything with a handler is a `.client.tsx` leaf. The glyphs the visual draws live in `slide-shared/glyphs/`. Output views of an example result live in `outputs/` and are chosen by `OutputView` (`output-dispatch.tsx`) from the handoff `kind`: `text`, `spec`, `tickets`, `research`, `comparison`, `requirements`. The tickets view is the dependency graph: the parent holds the ticked ids, a click on a ready ticket ticks it and readies what it blocked.

## Adding a Workflow

1. Copy `summer-party.config.yml` to `<id>.config.yml` and `summer-party.config.de.yml` to `<id>.config.de.yml`. The English file holds the data (stages with `id`, `moves: [B, ...]` and `gate`; jobs with `dependsOn`, `inputs`, `outputs`, `skills`, `fanOut`, `focalJob`) and `words:`; the German file holds `words:` only, under exactly the same key paths. Handoff keys (`kind`, `text`, ...) stay English in both languages.
2. The words per stage: `name`, `moves.<Letter>` (the tooltip of each listed BRIEF letter, why it applies to this stage) and, on the stage holding the focal job, `card: { label, lines, status }`. The first stage is named Plan and the last Review (German Prüfen). The words per job: `title`, `detail?`, `description`, `run: { todo, prompt, short?, shortCommand? }`, `command?`, `check: { todo, criteria, prompt }`, `page?: { todo, simple, technical }`, `exampleInput`/`exampleOutput` in fenced `handoff` blocks, `parked?`. Every prompt is complete as pasted: a result of an earlier job is inlined as its example handoff under one line saying to replace it with your own, and the loader rejects any `{{slot}}`. `run.short` is the short grill of an interview job only, and `run.shortCommand` is its Technical twin (the `command` plus a short-version suffix), so the Short toggle shows and works at both levels. A research job's prompt names no candidate: it starts by naming three real ones in the spec's city, lets the viewer pick one, then checks it. A `command` shows in Technical and is copied as written: write it self-contained with the example data inline, no bracketed placeholder (the loader test rejects `[...]`). A `page` has `simple` (one self-contained HTML file) and `technical` (write a temporary .html file, serve it on localhost, open the browser). In German every prompt, check, page and command says `Antworte auf Deutsch`.
3. Register it in `workflow-data.ts`: import both files, add the id to `WORKFLOW_IDS` and the pair to `PAIRS`. The picker lists `WORKFLOW_IDS` in order.
4. Run `npm run verify`. `workflow-data.test.ts` loads every pair in both locales (the build throws each problem of a shipped pair, see `workflow.pure.ts` and `workflow-checks.pure.ts`) and holds the German keys equal to the English ones.
5. Viewers may also upload a Workflow file (same shape, one file with its own words); problems are listed under the toolbar and the authored Workflow stays.

The output labels (Goal, Done, Waiting, …) are the `output:` tree of `human-in-the-loop.config.yml` and its German twin, not part of a Workflow; English comes from that file alone, with no copy in code.

## Testing

- Fast suite: `*.pure.test.ts` and `*.test.ts` beside the files (Workflow loading, view model, state, handoff parsing, ticket graph, output dispatch, German parity).
- Browser seam: `human-in-the-loop.browser.test.ts`, local only (`npm run test:browser`), drives the Slides Episode's "Human in the loop" Slide in the shared headless Chrome: the pill toolbar, a stage's Try it modal (title with learning goal, the simple/technical toggle and X, two columns on desktop with the details following the focused task, full screen on a phone with the details folded under each task, Chat 1..N tabs and the Technical orchestrator, "Open in" written out or icon only, collapsed prompts, copy, chat links, "Copied", backdrop, X and Escape close), the Short toggle, the example spec and ticket graph, ticking a ticket, Vacation with its own card lines and the Technical setup and `/skill` copy, a broken and a valid upload, axe in light and dark, and phone width. `HITL_URL` names the page (default `http://localhost:3000/episodes/slides/`), served by `next dev` or `npm run preview`.
- Episode text captures (`tests/…/episode-text`) include the toolbar words; recapture them when a word changes.

## New schema (issue 283, beside the old one)

`summer-party.en.yml` is the English summer party in the new schema (`workflow-schema.types.ts`): one language per file, markdown handoffs checked against their template's `kind` and H2s, slots that name earlier outputs (the diagram's edges come from them), and prompts as sections that the popover hands to TryPrompt. `loadWorkflow` in `workflow-loader.pure.ts` reads it; `workflowFor` routes any pair listed in `NEW_FILES` through it and the rest through the old loader. The German summer party and both vacation files stay on the old schema until issue 286 moves them and removes the old path.
