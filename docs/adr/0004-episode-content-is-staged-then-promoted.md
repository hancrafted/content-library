# Episode content is staged in docs and harvested at Promotion

> Amended by _Content data model_ (0016): Promotion also resolves each Slide instance at a Gate: update the shared Slide or become its own Slide.
> Amended by _Content data model_ (0016, _Pipeline and evidence_): research may be reused, so the Research stage can be empty; a refresh keeps its id; Promotion confirms `confidence` and `informs` and merges duplicates.

A new Episode's text starts as markdown in a staging folder, `docs/episodes/<slug>/`: a Brief, research files, a Dossier and then the Spec. The implementation is built and iterated from those files, and they stay the source of truth through the feedback loop and practice. When the Episode is final it is promoted: Staging is harvested into lessons, cleanups and tickets, the Spec's design Options are filed into the Design archive, the Brief moves beside the Episode, and the staging folder is deleted. From then on the Slide folders, code and `i18n/`, are the only source of the Episode's words.

## Why the Slide's `i18n/` and not a `slide.md`

This record first planned to move each Slide's words into a `slides/<slug>/slide.md` at Promotion, with a parity test holding `i18n/en.json` equal to it. By the time the first Episode was ready, `i18n/en.json` already held every word that file would carry: the title and caption, the Voice script as `voiceScript.segments`, and each Speaker note with its header, description and sources, with German beside it in `de.json`. A `slide.md` would have been a second copy kept equal by a test, the failure this record names for the Manuscript below. One owner per Slide still holds, and the text still travels with the Slide folder (design-ADR _The Slide is a self-contained folder_). An agent reads an Episode's words as markdown with `npm run episode:text`, a reading copy generated on demand and never committed.

## Why one Dossier, not a Dossier and a Manuscript

Run 1 kept a Dossier (spine, Visuals, Speaker notes, Segment beats) and a Manuscript (the spoken prose, one paragraph per Segment). The Manuscript was a rendering of the Dossier: it copied the spine verbatim, a test existed only to keep the two agreeing, and still 6 of 9 Slides shipped a different title than their Manuscript h3. One staging file gives Han one file to review, one gate and one draft-to-approved diff. Two jobs still write it: `write-dossier` the plan, `write-voice-script` only the Voice script blocks, so a failed tone line reruns only the voice.

## Why a Design archive and not the Spec

The Spec holds every Option the designers drew, most of them rejected, and Han's reasons for each pick. That is worth keeping to reuse a design idea in a later Episode, but not as a source: the code is the picked design. So Promotion files each Slide's Options, its Visual idea, its feedback and its designer prompts into one static page, `design-archive/<slug>/index.html`, browsed locally and never deployed, and deletes the Spec. The archive is generated by script from the Spec and the run log, so it is a record of the Run and is never edited.

## Decisions

1. **Staging holds the work in progress.** `docs/episodes/<slug>/` holds `brief.md`, `research/*.md`, `reference/*/design-reference.md` with its page images, `dossier.md` until the Spec Gate, `spec/spec.html` (the Spec, design-ADR-0011, which replaces design-ADR-0008's `spec/spec.md` and `spec/design-spec.md`), `research-plan.md` and `feedback/NN/feedback.md` (an Episode branch begun earlier keeps its `run-log.md`). Content changes from the feedback loop land in the Spec first, then in the implementation: from the Spec Gate on, the Spec is the only source and the Dossier is deleted (amended by design-ADR-0011; before, they landed in the Dossier). A `verified` entry `{ by: human:han, at }` at or after `generated.at` means Han accepted the file at its gate (see design-ADR-0005); every staging file carries `status: draft`, and Promotion is marked by the file's location.
2. **Promotion happens when the Episode is final**, in any order with German translation and publishing. The `episode-promote` skill runs it, and no words move:
   - The run log and its `pipeline.yml` are archived to `.logs/new-episode/<slug>/`, a folder the dashboard opens, with the Brief and the Spec as the Run left them: a record of the Run, never a source.
   - The Spec's Options, with each Slide's Visual idea, feedback, designer prompts and cited design references, are filed into `design-archive/<slug>/`.
   - Staging is harvested: lessons, style, Slide library candidates and cleanups are proposed, Han approves them at one gate, and larger refactors are filed as tickets.
   - `brief.md` moves to `src/components/episodes/<ep>/`, its `status: draft` removed.
   - Every research file moves to `docs/llm-wiki/research/<category>/` and is listed in `docs/llm-wiki/index.md` under its category's h3, by `npm run episode:promote-research` (amended: it first moved only research a Slide still cites. A Slide cites a source URL, not a research file, and no one judges whether a citation earns its place, so keeping research no longer waits on that judgment. The wiki grows with every Run instead; organizing it is its own problem).
   - The staging folder, the Spec with it, is deleted after the harvest has read it. git history keeps it.
3. **After Promotion, each Slide has one owner of its words:** its `i18n/<locale>.json`. `<ep>.ts` and its Section markers own Slide order.
4. **German is a translation of `i18n/en.json` into `de.json`**, before or after Promotion.
5. **Headings carry explicit slugs**, `### <title> {#slug}`, because the slug becomes a folder name, a Translation key and a published anchor, and must survive a retitle.

## Considered options

- **Move each Slide's words into `slide.md`, with a parity test against `en.json`.** The first version of this record. Rejected for the duplication above.
- **A guide file (`AGENTS.md`) per Slide or per Episode**, recording its purpose and design decisions. Rejected for now: the Design archive and the Brief carry the decisions, and its map of the code would drift unchecked. Added when agents are seen to misread a Slide.
- **Keep the Spec whole** beside the code, or in `docs/`. Rejected: a 500K page of mostly rejected mocks in the code folder, where the Design archive keeps what is reused from it. A copy stays in `.logs/` as the Run's record, beside its log, which nothing builds from.
- **Generate `i18n/*.json` or `<ep>.ts` from markdown.** Rejected: it ties the app to a document format that is not stable, and design-ADR _The Slide is a self-contained folder_ already rejected a generator.

## Consequences

- The Archgate ADRs need no amendment for promoted text: no markdown joins a Slide folder. `brief.md` sits in the Episode folder.
- `design-archive/` is committed, kept out of Prettier and out of Tailwind's source scan, and served by `npm run design-archive`.
- The design references a Slide cites survive Staging only as copies in the Design archive.
