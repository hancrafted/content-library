# Handoff: harness findings from the Slide master prototype run

For an agent fixing the harness after PR #50 (`slide-master` Episode). Each item names the evidence, a proposed fix, and whether a human decision is needed first. Items marked **decide** wait for the user; the others are ready to execute.

Context:

- The run built 18 page Slides with sub-agents. Each Slide was merged one at a time, with `npm run verify` after every merge.
- All checks pass on the branch. The findings below are what the harness got wrong, made awkward, or never saw.
- Exceptions to an ADR need a separate ADR and human approval (every ADR's "Exceptions" line).

## 3. Open questions for the user

1. **Glossary clash:** the slug `slide-master` collides with GLOSSARY/FE-002 "Slide master" (the shared frame in `src/components/slide-master/`). Rename the Episode (it is a layout reference, so no published link yet), or add an Avoid note?
2. **`parts/` for one Slide:** FE-002 §3.4 says `parts/` holds parts several Slides share, while §7.2 forces Episode CSS into `parts/`. Single-Slide components with CSS currently sit in `parts/`: centre spine, sticky years, grids 1×1 and 3×3, bento CSS. Allow it explicitly, or add `slides/<slide>.module.css`?
3. **Shared Slide helpers:** should the popover placement hook and a reveal-once hook (repeated in 5 widgets) be extracted, or does FE-007 §4 (ungoverned Slide internals) win?

   - metro: a legend label
   - scroll-snap: a "card n of 6" announcement
   - sticky-years: category names
   - Add them now, or leave the placeholders?
5. **Answered in code, confirm:** stepper state words were added by the orchestrator (`vertical-stepper.states.*`).
